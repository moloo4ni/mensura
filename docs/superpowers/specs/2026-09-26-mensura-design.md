# Mensura — метроном-плагин для fooyin

Дата: 2026-09-26
Целевая версия fooyin: 0.13.1 (SDK из `/usr/include/fooyin`, CMake-пакет `Fooyin`).

## 1. Цель

DSP-плагин, который подмешивает щелчки метронома в играющий трек. Сценарии: игра на
инструменте под трек, тренировка ритма, проверка темпа записи.

Критерии успеха:
- клики звучат в такт треку при верном BPM и выставленной фазе;
- после перемотки клики сразу стоят на сетке новой позиции;
- на паузе/остановке кликов нет;
- BPM берётся из тега, при его отсутствии — ручное значение;
- управление — из виджета раскладки fooyin без открытия диалогов.

Не входит в объём (YAGNI): автоматическое определение долей (beat tracking),
пользовательские WAV-сэмплы, дробление долей (восьмые, триоли), запись BPM в теги,
хранение BPM/фазы отдельно для каждого трека, глобальные хоткеи.

## 2. Требования

### 2.1 Источник BPM
- Режим **Авто**: если у трека есть валидный тег BPM — используется он; иначе — общее
  ручное значение.
- Режим **Ручной**: всегда ручное значение.
- Ручное значение одно на все треки и сохраняется между сессиями.
- Ручное изменение BPM в виджете в режиме Авто переключает режим в Ручной.
- Разбор тега: из строки извлекается первое число (`"128"`, `"127.9"`, `"128 BPM"`);
  если числа нет или оно ≤ 0 — тега нет. Значение обрезается в диапазон 20–300.
- Изменение метаданных текущего трека на лету (`currentTrackUpdated`) пересчитывает BPM.

### 2.2 Фаза
- Сетка: доля *n* звучит в момент `t_n = phaseNs + n · 60e9 / bpm` (время трека, нс,
  *n* ∈ ℤ). Индекс в такте = `n mod beatsPerBar` (floor-деление), индекс 0 — акцент.
- **Tap**:
  - в Ручном режиме, а также в Авто без тега, серия из ≥ 2 нажатий задаёт ручной темп
    (среднее по последним до 8 интервалам) и фазу (последнее нажатие = доля с индексом 0);
    режим при этом не меняется;
  - в режиме Авто с тегом — только фаза: `phaseNs` выбирается так, чтобы доля с индексом
    0 пришлась на момент нажатия; темп остаётся из тега;
  - серия сбрасывается, если пауза между нажатиями > 2 с.
- **Смещение фазы** в мс (±1000) — ручная подстройка в меню ⚙; «Сбросить фазу» → 0.
- При смене трека фаза сбрасывается в 0.

### 2.3 Звук и такт
- Число долей в такте 1–16 (1 = без акцента).
- Первая доля такта — акцент: выше по тону и громче (+6 дБ относительно обычной доли).
- Тембры, синтезируемые кодом: «клик» (короткий импульс), «дерево» (woodblock), «бип»
  (синус). Длительность 30–60 мс, огибающая без щелчков на краях.
- Громкость кликов −40…0 дБ.
- Выключенный метроном не изменяет аудио.

### 2.4 Поведение при воспроизведении
- Пауза/остановка — кликов нет (DSP не вызывается), индикатор погашен.
- Перемотка — клики на сетке новой позиции, хвосты предыдущих кликов отброшены.
- Узел ставится в per-track DSP-цепочку, поэтому клики корректно проходят через
  кроссфейд вместе с треком.

## 3. Архитектура

Один плагин `fyplugin_mensura.so` (CMake, `create_fooyin_plugin` из `FooyinMacros.cmake`,
C++20, Qt6). Образец структуры — штатный `fyplugin_equaliser`.

Канал GUI → DSP — штатный механизм fooyin: виджет реализован как `DspLayoutEditor`,
любое изменение параметров отправляется сигналом `previewSettingsChanged(payload)`,
fooyin доставляет его в живой узел через `DspNode::loadSettings()`
(`supportsLiveSettings() == true`) и сохраняет в пресет DSP. Обратного канала DSP → GUI
нет: индикатор и Tap работают по слышимой позиции из `PlayerController`.

### 3.1 Компоненты

| Единица | Ответственность | Зависимости |
|---|---|---|
| `MensuraSettings` | POD-структура параметров: `enabled`, `bpm`, `beatsPerBar`, `sound`, `volumeDb`, `phaseNs`; плюс UI-состояние `mode`, `manualBpm`. Сериализация в `QByteArray` с номером версии; неизвестная версия / битые данные → `false`. | Qt Core |
| `BeatGrid` | Чистая математика сетки: доли в интервале `[t0, t1)`, индекс доли в такте, ближайшая доля к моменту `t`, фаза для «доля 0 в момент `t`». | — |
| `ClickSynth` | Синтез буферов клика для 3 тембров × {акцент, обычная} под заданный sample rate. | — |
| `MensuraDsp : DspNode` | Подмешивание кликов в аудиопотоке (раздел 4). | BeatGrid, ClickSynth, MensuraSettings |
| `TempoResolver` | Выбор BPM по режиму и тегу; разбор тега; источник (`Tag` / `Manual`) для отображения. | `Fooyin::Track` (чтение) |
| `TapTempo` | Темп и фаза по меткам нажатий (позиция трека, мс). | — |
| `PositionClock` | Интерполяция слышимой позиции: последнее `positionChanged` + `QElapsedTimer`; сброс на паузе, перемотке (`positionMoved`) и смене трека. | Qt Core |
| `MensuraWidget : DspLayoutEditor` | UI (раздел 5). | всё выше, `PlayerController` |
| `MensuraSettingsProvider : DspSettingsProvider` | `showAsLayoutWidget() == true`, `createLayoutEditor()` → `MensuraWidget`, `createSettingsWidget()` → диалог с теми же параметрами. | MensuraWidget |
| `MensuraPlugin` | Точка входа: `Plugin`, `CorePlugin`/`GuiPlugin` (получение `PlayerController`), `DspPlugin`, `DspGuiPlugin`. | fooyin |

`MensuraSettings`, `BeatGrid`, `ClickSynth`, `TempoResolver`, `TapTempo`,
`PositionClock` и `MensuraDsp` тестируются без запуска плеера.

### 3.2 Поток данных

Действие пользователя / событие плеера → `MensuraWidget` обновляет `MensuraSettings` →
`previewSettingsChanged(payload)` → fooyin → `MensuraDsp::loadSettings()` (возможно, в
аудиопотоке) → следующие буферы обрабатываются с новыми параметрами.

## 4. DSP-узел

- `id()` = `"fooyin.dsp.mensura"`, `name()` = `"Mensura"`, формат вывода = формат входа,
  `latencyFrames()` = 0.
- `prepare(format)`: запоминает sample rate и число каналов, синтезирует все 6 вариантов
  клика (3 тембра × 2), сбрасывает хвост.
- `loadSettings(payload)`: только копирование POD-полей и пересчёт линейного усиления из
  дБ; без аллокаций. Смена тембра — выбор указателя на заранее синтезированный буфер.
- `process(chunks)`: для каждого буфера интервал `[startTimeNs, startTimeNs + frames·1e9/rate)`;
  для каждой доли из `BeatGrid` в этом интервале клик подмешивается во все каналы со
  смещением в кадрах. Недописанный хвост клика сохраняется (позиция в буфере клика +
  вариант) и продолжается в следующем буфере. Если `startTimeNs` следующего буфера не
  равен ожидаемому (разрыв > 1 кадра) — хвост отбрасывается. Результат проходит через
  мягкий клиппер (только сэмплы, куда подмешан клик). Без аллокаций и блокировок.
- `reset()` / `flush(Flush)`: хвост отбрасывается. `flush(EndOfTrack)`: ничего не
  добавляет.
- `enabled == false` → `process()` возвращается сразу.
- Любое число каналов и любой sample rate.

## 5. Виджет

```
┌──────────────────────────────────────────────────────────────────────────┐
│ [● Mensura]  ♩ 128.0  тег ▾   [ TAP ]   ● ○ ○ ○   4/4 ▾   🔊 −6 dB  ⚙   │
└──────────────────────────────────────────────────────────────────────────┘
```

- **[● Mensura]** — вкл/выкл. Tooltip: «Добавьте Mensura в DSP → Per-track».
- **♩ BPM** — спинбокс 20–300, шаг 0.1, колесо ±1. В Авто с тегом — серый текст и метка
  «тег»; иначе метка «ручной».
- **Режим ▾** — «Авто» / «Ручной».
- **[TAP]** — раздел 2.2; также клавиша `T`, когда виджет в фокусе.
- **Индикатор долей** — `beatsPerBar` точек (при > 8 — компактная полоса), текущая доля
  подсвечена, доля 0 — цветом акцента; обновление таймером ~60 Гц только при
  воспроизведении, позиция из `PositionClock`.
- **N/4 ▾** — число долей 1–16.
- **🔊 дБ** — громкость −40…0.
- **⚙** — меню: тембр, смещение фазы (мс), «Сбросить фазу».
- При узкой ширине второстепенные элементы (индикатор, громкость) переносятся во вторую
  строку.

## 6. Ошибки и крайние случаи

- Битый/неизвестный payload → `loadSettings` = `false`, узел работает со значениями по
  умолчанию (выключен, 120 BPM, 4 доли, «клик», −6 дБ, фаза 0).
- BPM вне диапазона → обрезка до 20–300.
- Невалидный тег → считается отсутствующим.
- Нет текущего трека → BPM из ручного значения, индикатор погашен.
- Узел не добавлен в цепочку → виджет работает, звука нет; подсказка в tooltip.

## 7. Тестирование

### 7.1 Шаг 0 — проверка рисков (прототип)
Минимальный узел, логирующий `startTimeNs` и вызовы `loadSettings`. Проверить:
1. `startTimeNs` = позиция в текущем треке (сбрасывается на новом треке, скачет при перемотке);
2. `previewSettingsChanged` из layout-виджета доходит до узла в per-track цепочке во время
   воспроизведения;
3. путь пользовательских плагинов (`Core::userPluginsPath()`).

Если (1) или (2) не подтверждается — стоп, пересмотр архитектуры (вариант C: общее
состояние внутри `.so` как запасной канал).

### 7.2 Юнит-тесты (Qt Test, `ctest`)
- `BeatGrid`: доли на границах интервала, отрицательная фаза и отрицательные *n*, дробный
  BPM, отсутствие накопленной ошибки на 1-часовом треке, индекс в такте.
- `TapTempo`: темп по серии, сброс после паузы > 2 с, фаза = последнее нажатие.
- `TempoResolver`: разбор тегов (`"128"`, `"127.9"`, `"128 BPM"`, `"0"`, `"abc"`, пусто),
  выбор источника в обоих режимах.
- `MensuraSettings`: round-trip, битый payload, неизвестная версия.
- `PositionClock`: интерполяция, сброс на паузе/перемотке.
- `MensuraDsp` на синтетических буферах: клик начинается ровно в ожидаемом кадре; хвост
  через границу буфера; разрыв времени отбрасывает хвост; выключенный узел не меняет
  аудио; акцент на доле 0.

### 7.3 Ручная проверка в fooyin
1. Трек с тегом BPM: метка «тег», клики в темпе; Tap выравнивает фазу.
2. Трек без тега: ручное значение, метка «ручной»; Tap задаёт темп и фазу.
3. Перемотка: клики сразу на сетке.
4. Пауза/стоп: тишина, индикатор погашен; продолжение — клики на сетке.
5. Смена трека: фаза сброшена, BPM пересчитан.
6. Кроссфейд: клики уходят/приходят вместе с треками.
7. Смена тембра, громкости, числа долей на лету — без щелчков и сбоев.
8. Перезапуск fooyin — настройки сохранены.
